# AI Sana Challenge Hub

MVP для хакатона: бизнес превращает неполное описание в проверенную карточку задачи, студенческие команды предлагают решения, бизнес принимает или отклоняет предложения вручную.

## Архитектура

```text
React / Vite / TypeScript / Tailwind / React Router
                       ↓ HTTP / JSON
FastAPI api → business_logic → data_access → PostgreSQL
                    ↓
            OpenAI Python SDK
                    ↓
        Structured Outputs → Pydantic → проверка источников
```

`backend/app/api` — маршруты и контракты; `business_logic` — AI, переходы статусов и рейтинг; `data_access` — SQLAlchemy async и репозиторий; `core` — настройки. Две таблицы: BusinessTask и TeamProposal, UUID, FK с каскадным удалением, timestamps и CHECK constraints. Alembic управляет схемой. Отдельной модели Team нет: имя команды хранится в предложении.

## Запуск

Нужны Python 3.11+, Node.js 22+ и PostgreSQL (либо Docker). Команды выполняются из корня проекта, если не указано иначе.

1. Создайте `.env` по `.env.example`, если его ещё нет. **Не перезаписывайте существующий `.env`.** Ключ хранится только там. Переменные:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
DATABASE_URL=postgresql+asyncpg://sana:sana@localhost:5432/sana
FRONTEND_ORIGIN=http://localhost:5173
```

2. Запустите PostgreSQL:

```sh
docker compose up -d db
```

Либо создайте пользователя `sana`, базу `sana` на своём PostgreSQL и укажите соответствующий `DATABASE_URL`. Пароль `sana` в compose предназначен только для локальной демонстрации, порт привязан к localhost.

3. Установите backend:

```sh
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install -r backend/requirements.txt
cd backend
python -m alembic upgrade head
python -m app.seed
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Seed идемпотентный: 5 опубликованных задач разной заполненности (30, 65, 80, 100, 85 баллов) и 5 предложений. Это вымышленные демонстрационные данные. Повторный запуск не перезаписывает карточки и решения пользователя.

4. Во втором терминале:

```sh
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Swagger: http://127.0.0.1:8000/docs. Vite проксирует `/api` на backend; ключи и `.env` не входят в frontend. Production-сборка: `npm run build`; для deployment нужен reverse proxy `/api` на backend.

Для воспроизводимой установки проверенных версий используйте `backend/requirements.lock.txt` вместо `requirements.txt`, а во frontend — `npm ci` (есть `package-lock.json`).

## Локальные переносимые инструменты Windows

Если инструменты были скачаны в `.tools` при разработке, `scripts/start-local.ps1` запускает изолированный PostgreSQL на порту 55432, миграцию, seed, backend и Vite без установки системных служб. Папки `.tools` и `.pgdata` исключены из Git. Скрипт не требует менять ключ в `.env`. Зависимости должны быть предварительно установлены.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1
# Остановка только процессов этого запуска:
powershell -ExecutionPolicy Bypass -File scripts/stop-local.ps1
```

## AI flow и источники

`POST /api/tasks/analyze` принимает `description`. OpenAI `responses.parse` возвращает Pydantic TaskAnalysis: известные идентификаторы missing_fields и минимум 3 непустых вопроса. После ответов `POST /api/tasks/generate` возвращает редактируемую Card.

Генерация намеренно экстрактивная: для каждого поля AI возвращает значение и дословную цитату из первоначального описания или ответа пользователя. Backend принимает значение только если оно равно цитате и действительно присутствует в источнике. Тексты вопросов не считаются фактами. Неизвестные сведения остаются null. Это ограничивает перефразирование, зато исключает появление новых неподтверждённых чисел, контактов и сроков. Смысловую корректность распределения по полям всё равно проверяет человек.

AI не рассчитывает рейтинг, не публикует карточки и не выбирает команды. Ошибка API, отказ или невалидный ответ обрабатываются; предусмотрена одна повторная попытка. После двух неудач интерфейс предлагает понятную ошибку и возможность заполнить карточку вручную. Нет скрытой подмены AI демоданными. Запросы используют `store=False`.

Интеграция: [официальная документация Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Рейтинг

Обычная функция `calculate_rating` в Python, никаких вызовов LLM:

| Сведения | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт **и** формат взаимодействия вместе | 10 |

Непустое поле после strip получает баллы. 0–39: draft; 40–69: working; 70–89: ready; 90–100: priority. Рейтинг измеряет полноту, а не достоверность или качество решения. Заголовок и отрасль баллов не дают. API возвращает score, level, missing и improvements. Форма получает предварительный рейтинг из `/api/tasks/preview`, после сохранения рейтинг записывается в БД.

## Публикация, каталог и предложения

Переходы: `draft → confirmed → published`. Для подтверждения достаточно названия; неполные карточки разрешены. Любое сохранение изменений возвращает задачу в draft, требует повторного подтверждения и публикации; связанные предложения сохраняются.

В каталоге только published. По умолчанию сортировка по убыванию рейтинга, затем дате и UUID. Есть сортировка по новизне, фильтры по точной отрасли и уровню. Низкий рейтинг не скрывает опубликованную задачу.

Команда отправляет имя, идею, план, оценку сроков и необязательную HTTP(S)-ссылку на прототип. Число предложений не ограничено. Начальный статус pending, бизнес вручную меняет его на accepted или rejected. Можно принять несколько команд и пересмотреть решение.

Это локальный демо-режим без авторизации: общий кабинет бизнеса доступен всем. Не размещайте его как публичный сервис с реальными контактами без добавления контроля доступа.

## Проверки

```sh
cd backend
python -m pytest -q
python -m alembic check
cd ../frontend
npm run build
npx playwright install chromium
npm run test:e2e
```

Backend integration test использует настроенный PostgreSQL, создаёт свою задачу и удаляет её в finally. AI в автоматических тестах подменён, чтобы не тратить API-кредиты; отдельный реальный smoke test `python scripts/live_ai_smoke.py` из корня проверяет OpenAI через ваш ключ и делает два платных запроса. Он печатает только поля карточки, не ключ.

Browser test требует работающие backend и frontend. Полный UI flow подменяет только два AI endpoint; остальное проходит через реальный backend и PostgreSQL. Второй тест проверяет отображение ошибки AI.

Если Chrome уже установлен, вместо скачивания Chromium можно указать `$env:PLAYWRIGHT_CHANNEL = 'chrome'` в PowerShell. Третий тест `tests/live.spec.ts` по умолчанию пропускается. Для полного прогона с реальным OpenAI (два платных запроса): `$env:LIVE_AI = '1'; npx playwright test tests/live.spec.ts`. Он также проверяет мобильную ширину и сохраняет скриншоты в `.tools`. Браузерные тесты оставляют созданные демонстрационные карточки и предложения в кабинете.

Для backend-тестов на переносимой локальной базе перед запуском установите `$env:DATABASE_URL = 'postgresql+asyncpg://sana@127.0.0.1:55432/sana'`. Скрипт запуска задаёт эту переменную только своим дочерним процессам, не меняя `.env`.

## Пятиминутное демо

1. Каталог: сравните рейтинг 5 демозадач, фильтры и сортировку.
2. Создать задачу: «Хотим с помощью ИИ уменьшить очереди в нашей клинике.» → «Уточнить с AI».
3. Ответьте на вопросы своими фактами. Часть ответов можно оставить пустыми.
4. Сформируйте карточку, проверьте поля, исправьте название и подтвердите сведения. Обратите внимание на исходный рейтинг.
5. Добавьте пользователей, доступные данные, результат, критерии, ограничения, контакт и формат связи. Рейтинг вырастет. Подтвердите обновлённые сведения → «Опубликовать».
6. В каталоге найдите задачу на позиции согласно рейтингу, откройте детали.
7. Отправьте предложение от команды, например «Qadam», с идеей и планом.
8. Откройте «Предложения команд» → «Принять». Статус изменится на «Принято» только после вашего действия.

При недоступности OpenAI проверьте ключ, доступ к выбранной модели и лимиты; сообщение в UI сохраняет введённый текст. При ошибке БД проверьте PostgreSQL, DATABASE_URL и миграцию. HTTP 404/422/409 обрабатываются в интерфейсе.
