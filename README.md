# 🚀 AI Sana Challenge Hub

> Платформа, которая помогает бизнесу превратить сырую идею или проблему в качественно сформулированную задачу для студенческих команд.

Проект разработан в рамках практического хакатона **AI Sana / HackAlem**.

Главная идея: бизнесу не нужно заранее уметь составлять техническое задание. Пользователь описывает проблему своими словами, AI помогает определить недостающую информацию и задаёт уточняющие вопросы. После этого формируется структурированная карточка задачи, рассчитывается её рейтинг готовности, а задача публикуется в общем каталоге для студенческих команд.

---

## 🎯 Проблема

Бизнес часто понимает свою проблему, но не всегда может превратить её в качественно сформулированную задачу.

Например:

> «Хотим с помощью ИИ уменьшить очереди в нашей клинике».

Из такого описания непонятно:

- где именно возникают очереди;
- кто будет пользоваться решением;
- какие данные доступны;
- какие существуют ограничения;
- какой результат ожидает бизнес;
- как будет измеряться успех проекта.

Из-за этого студенческой команде сложно оценить задачу и начать работу без дополнительных уточнений.

---

## 💡 Решение

**AI Sana Challenge Hub** помогает пройти путь от первоначальной идеи бизнеса до готовой задачи.

Основной сценарий:

```text
Бизнес вводит описание
        ↓
AI анализирует черновик
        ↓
Определяет недостающую информацию
        ↓
Генерирует минимум 3 уточняющих вопроса
        ↓
Бизнес отвечает
        ↓
Формируется Task Card
        ↓
Бизнес редактирует и подтверждает данные
        ↓
Рассчитывается рейтинг готовности 0–100
        ↓
Задача публикуется в каталоге
        ↓
Студенческие команды отправляют предложения
        ↓
Бизнес сравнивает предложения
        ↓
Accept / Reject
```

AI помогает сформулировать задачу, но **не принимает решение за бизнес**.

---

# ✨ Основные возможности

### 🤖 AI-анализ задачи

Пользователь может написать задачу обычным человеческим языком.

Система анализирует описание и определяет, какой информации недостаточно.

Например:

```text
Хотим с помощью ИИ уменьшить очереди в нашей клинике.
```

AI может определить отсутствие:

```text
- информации о пользователях;
- доступных данных;
- критериев успеха;
- ограничений.
```

После этого система генерирует минимум три релевантных уточняющих вопроса.

---

### 📝 Structured Task Card

После получения ответов формируется структурированная карточка.

Она содержит:

- название;
- контекст;
- потребность;
- пользователей;
- доступные данные и материалы;
- ограничения;
- ожидаемый результат;
- критерии успеха;
- контакт;
- формат взаимодействия с бизнесом.

AI не должен придумывать отсутствующие факты.

Перед публикацией пользователь может изменить любые сгенерированные данные и вручную подтвердить карточку.

---

# 🏆 Readiness Score

Каждая бизнес-задача получает рейтинг готовности:

```text
0 ─────────────────────────────── 100
```

Рейтинг показывает не размер или известность компании, а то, **насколько задача готова к реальной работе со студенческой командой**.

## Формула

| Показатель | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Всего** | **100** |

Рейтинг рассчитывается **обычной бизнес-логикой приложения**, а не LLM.

Это делает оценку:

- прозрачной;
- воспроизводимой;
- объяснимой пользователю.

## Уровни готовности

| Score | Level |
|---:|---|
| 0–39 | Draft |
| 40–69 | Working |
| 70–89 | Ready |
| 90–100 | Priority |

После редактирования и подтверждения информации рейтинг пересчитывается.

Низкий рейтинг не запрещает публикацию задачи — он показывает, какой информации ещё не хватает.

---

# 🎮 Геймификация

Основная геймификация направлена на **качество бизнес-задачи**.

```text
Больше полезной информации
        ↓
Выше Readiness Score
        ↓
Выше уровень готовности
        ↓
Лучше позиция в каталоге
```

При этом пользователь видит:

- текущий score;
- полученные баллы;
- отсутствующие сведения;
- рекомендации по улучшению карточки.

Таким образом рейтинг не просто оценивает задачу, а мотивирует бизнес сделать её понятнее для исполнителей.

---

# 📚 Каталог задач

После подтверждения задача может быть опубликована в общем каталоге.

Каталог позволяет:

- просматривать доступные задачи;
- сортировать их по рейтингу;
- фильтровать по тематике;
- фильтровать по уровню готовности;
- открывать подробную карточку.

Все опубликованные задачи остаются доступными студентам независимо от рейтинга.

---

# 👨‍💻 Предложения команд

Студенческая команда может открыть интересующую задачу и отправить предложение.

Предложение содержит:

```text
Название команды
Идея решения
План реализации
Оценка сроков
Ссылка на прототип
```

Количество предложений для задачи не ограничивается.

---

# 🤝 Решение бизнеса

Бизнес получает список предложений команд.

Для каждого предложения доступны ручные действия:

```text
[ Accept ]

[ Reject ]
```

Бизнес может:

- выбрать одну команду;
- выбрать несколько команд;
- не выбрать ни одной.

**AI не назначает исполнителей автоматически.**

---

# 🤖 Где используется AI

AI используется только там, где действительно требуется понимание естественного языка.

### AI выполняет

```text
Черновик бизнес-задачи
        ↓
Semantic analysis
        ↓
Missing information detection
        ↓
Clarification questions
        ↓
Structured Task Card
```

Основные AI-функции:

1. анализ первоначального описания;
2. поиск недостающей информации;
3. генерация уточняющих вопросов;
4. структурирование предоставленной пользователем информации.

---

## Где AI НЕ используется

Мы намеренно не используем LLM для задач, где обычный код надёжнее.

Например:

```text
Readiness Score
CRUD
Validation
Catalog sorting
Filtering
Accept / Reject
Database operations
```

Это позволяет избежать непредсказуемых результатов там, где требуется deterministic logic.

---

# 🧠 AI Structured Output

Backend не должен полагаться на произвольный текст модели.

Для AI-анализа используется структурированный формат.

Пример:

```json
{
  "missing_fields": [
    "users",
    "data_and_materials",
    "success_criteria"
  ],
  "questions": [
    "Кто будет пользоваться решением?",
    "Какие данные уже доступны?",
    "По каким показателям будет измеряться успех?"
  ]
}
```

Полученные данные проходят валидацию перед дальнейшим использованием.

## 1. Клонирование

```bash
git clone <repository-url>
cd <repository-name>
```

---

## 2. Environment variables

Создайте `.env` на основе:

```text
.env.example
```

Пример:

```env
OPENAI_API_KEY=your_openai_api_key

DB_HOST=localhost
DB_PORT=5432

DB_USER=postgres
DB_PASSWORD=postgres
```

⚠️ Реальные API keys нельзя добавлять в Git.

`.env` должен находиться в `.gitignore`.

# 🐍 Backend

Перейдите в backend:

```bash
cd backend
```

Создайте virtual environment:

### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Запустите backend:

```bash
uvicorn app.main:app --reload
```

После запуска API обычно доступно по адресу:

```text
http://localhost:8000
```

Swagger:

```text
http://localhost:8000/docs
```

```text

          ↓

          ↓
```

```text
          ↓
```

```text
          ↓
5. Structured Task Card
          ↓

          ↓
8. Score увеличивается
          ↓
9. Publish
          ↓
10. Catalog
          ↓
11. Team Proposal
          ↓
```

Цель — показать весь сценарий как **работающий продукт**, а не как набор отдельных экранов.

# 🧯 Обработка ошибок

Приложение должно корректно обрабатывать основные ошибки:

### OpenAI API недоступен

Пользователь получает понятное сообщение вместо падения приложения.

### AI вернул некорректные данные

Structured Output проходит validation.

Невалидные данные не сохраняются в БД.

### Задача не существует

Backend возвращает корректный HTTP status.

### Ошибка базы данных

Ошибка обрабатывается backend-ом и не раскрывает пользователю внутренние данные системы.

# 🚫 Что намеренно не входит в MVP

Из-за ограниченного времени хакатона мы не усложняем проект функциями, которые не нужны для демонстрации основной ценности.

Не являются приоритетом:

- полноценная система регистрации;
- восстановление паролей;
- сложная ролевая модель;
- realtime chat;
- notifications;
- calendar;
- file storage;
- собственная ML-модель;
- vector database;
- RAG;
- Kubernetes;
- microservices;
- полноценный project management system.

Приоритет:

> **Working end-to-end scenario > unnecessary infrastructure**
