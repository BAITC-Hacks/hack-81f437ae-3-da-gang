# Архитектура MVP

Браузер → HTTP API на Node.js → доменная логика → JSON-файл.
Один процесс, один порт, без сборки и внешних зависимостей. Это заготовка для
хакатона, а не многопользовательский production-сервис.

## Сущности

**Task:** id, title, problem, outcome, successCriteria, resources, deadline,
status, createdAt, updatedAt, proposals[], selectedProposalId.

**Proposal:** id, teamName, message, createdAt.

Переходы: `draft → published → matched`. Редактирование разрешено в черновике.
Отклики доступны только в `published`. Выбрать можно ровно один существующий отклик.
В дальнейшем User/Organization/Team выносятся в отдельные сущности, а у задачи
появляется ownerId. Проверка прав должна происходить на сервере.

## Рейтинг

| Критерий | Минимум символов | Баллы |
|---|---:|---:|
| Название | 8 | 10 |
| Проблема | 40 | 25 |
| Ожидаемый результат | 30 | 25 |
| Критерии успеха | 20 | 20 |
| Ресурсы | 15 | 10 |
| Срок | 5 | 10 |

Для публикации нужны первые три критерия и минимум 60 баллов.
Уровни: 60 — бронза, 75 — серебро, 90 — золото. Каталог сортируется по убыванию
баллов, при равенстве — сначала новые задачи. Выбранная команда отображается в карточке.
Порог длины — прозрачная начальная эвристика, которую можно обмануть бессмысленным текстом.
Смысловая оценка и AI-помощник — следующий этап, а не уже реализованная возможность.

## API

| Метод | Путь | Действие |
|---|---|---|
| GET | /api/tasks | Все задачи для демо-кабинета |
| GET | /api/tasks?catalog=1 | Опубликованные задачи, включая закрытые |
| POST | /api/tasks | Создать черновик: поля Task |
| PATCH | /api/tasks/:id | Обновить поля черновика |
| POST | /api/tasks/:id/publish | Опубликовать |
| POST | /api/tasks/:id/proposals | Отклик: teamName, message |
| POST | /api/tasks/:id/select | Выбор: proposalId |

Ошибки: `{ "error": "сообщение" }`; статусы 400, 404, 409, 413, 500.
Ответ с задачей включает вычисляемое поле `rating` с баллами и проверками.

## Что добавить перед публичным размещением

- Вход, роли, владельца задачи, идентификацию команды и серверную проверку прав.
- PostgreSQL/SQLite с миграциями и транзакциями вместо локального JSON.
- Ограничение частоты запросов, журнал событий и резервное копирование.
- Приватность откликов: их видят автор команды и владелец задачи.
- AI-помощника через серверный адаптер: уточнения, предложение структурированной карточки,
  объяснимый рейтинг. Сохранять изменения только после принятия пользователем.
- Хранение API-ключа только на сервере, таймауты и обработку недоступности AI.
