# Аудит существующего HackAlem / AI Sana MVP

Проверено 23 сентября 2026. Проект не пересоздавался; структура React → FastAPI → Service → Repository → PostgreSQL сохранена.

## 1. Что реально работает

- React/Vite/TypeScript/Tailwind и React Router: создание, вопросы, редактор, рейтинг, каталог, детали, отправка предложения и кабинет бизнеса. Swagger для demo не нужен.
- OpenAI Python SDK `responses.parse`: анализ описания и минимум три разных вопроса, генерация карточки со Structured Outputs и Pydantic. В рабочем приложении запросы идут в OpenAI, не в mock.
- Backend пропускает в AI-карточку только точные цитаты из описания/ответов. Неизвестное остаётся null; распределение по полям проверяет человек.
- Python-рейтинг с весами 20/20/15/15/10/10/10, уровнями и подсказками. Неполная опубликованная задача остаётся в каталоге.
- PostgreSQL и SQLAlchemy async: карточки, предложения, решения и дополнительные планы пилотов. Миграции `0001` и `0002`, FK с ON DELETE CASCADE, UUID, ограничения статусов/рейтинга, индексы, timestamps.
- Подтверждение и публикация отдельными действиями; редактирование возвращает карточку в draft. Можно принять несколько команд и пересмотреть решение.
- Дополнительные функции сохранены: разбор качества, уточнения, помощник предложения, таблица сравнения, пилот и печать/PDF.

## 3. Частичные возможности и границы

- Переключатель ролей — режим интерфейса, не авторизация. Общий кабинет намеренно соответствует объёму хакатона.
- Цитаты AI отображаются при первичной проверке карточки; постоянной истории цитат нет.
- Рейтинг измеряет заполненность, не достоверность данных и не коммерческую ценность.
- AI-разбор качества формулирует вопросы с проверенными цитатами; это не гарантия отсутствия всех противоречий.
- PDF создаётся через печать браузера, серверного хранения файлов нет.
- ORM-связь используется через FK и явные запросы Repository; отдельный `relationship()` для текущих операций не требуется.

## 4. Найденные и исправленные проблемы

1. В `.env.example` было значение ключа OpenAI. Значение удалено, `.env` не изменялся. Добавлены `scripts/check_secrets.py` и regression tests. Проверка выводит только путь/номер строки, никогда ключ. Владельцу необходимо отозвать/заменить ключ, попавший в шаблон.
2. `start-local.ps1` считал существующий PID-файл доказательством работающих процессов. Теперь проверяются путь, командная строка и время старта; остановленный сервис восстанавливается отдельно, живой не дублируется. Скрипт ждёт HTTP-готовности. `stop-local.ps1` использует те же проверки, чтобы не остановить чужой процесс с повторно использованным PID.
3. `/api/health` раньше отвечал OK без проверки БД. Теперь читает обе таблицы через async session; недоступная БД/схема возвращает безопасное сообщение 503.
4. Три одинаковых AI-вопроса проходили проверку длины списка. Теперь вопросы нормализуются, повторы удаляются; меньше трёх различных вопросов приводит к повторной попытке и затем понятной ошибке. Пустой ключ из пробелов также обрабатывается как отсутствие ключа.
5. Обнаружена гонка загрузки предложений: запоздавший GET мог заменить свежий Accept в UI старым pending. Теперь эффект загрузки отменяет устаревшие запросы, ошибки загрузки отделены от решений, изменение массива использует актуальное состояние. Добавлен браузерный сценарий с задержанным GET.
6. Фильтры каталога получили явные доступные имена. Реальный browser test теперь проверяет отрасль, уровень, сортировку и сохранение принятия/отклонения после перезагрузки.

## 5. Обязательный flow

Пропусков в обязательном flow не обнаружено после проверки и исправлений. Прогон `live.spec.ts` использует ровно исходную фразу из задания: «Хотим с помощью ИИ уменьшить очереди в нашей клинике.»

Проверены ввод → настоящий запрос OpenAI → минимум 3 разных вопроса → ответ → редактируемая карточка → низкий исходный рейтинг → ручное дополнение → 100 баллов → подтверждение → публикация → место в каталоге по рейтингу → фильтры → предложение команды → Accept → перезагрузка → Reject → перезагрузка → повторный Accept.

Это учебный сценарий: реальные данные пациентов и клиник для теста не использовались. Контактный адрес example.com вводится после AI-вызовов и сохраняется только в локальной БД.

## 6. Доказательства проверки

- **23 backend-теста прошли**: рейтинг, grounding, источники, невалидный AI, недоступный API, ошибки БД, основной flow и пилоты, секреты/ignore rules.
- **TypeScript и production-сборка Vite прошли**, Python imports/compileall проверены.
- **4 браузерных теста прошли**, включая настоящий OpenAI flow, восстановление статуса после reload и дополнительные функции пилота/PDF.
- `alembic check` не обнаружил расхождений моделей и схемы.
- На отдельной временной пустой PostgreSQL-базе выполнены обе миграции и два запуска seed: осталось ровно 5 задач / 5 предложений. Временная база после проверки удалена; рабочая база сохранена.
- Проверено восстановление остановленного frontend при сохранении живого backend и идемпотентность повторного запуска.
- Сканирование исходников и production assets после сборки: 0 совпадений с шаблоном API-ключа; `.env.example` пустой. Это проверка известных шаблонов, не универсальная гарантия отсутствия любых секретов.

## Что нельзя утверждать

В `C:\hackalem` нет `.git`: `git ls-files` сообщает «not a git repository». Поэтому невозможно проверить историю коммитов или утверждать, что старого ключа никогда не было в Git. Реальные правила `.gitignore` проверены в отдельном временном репозитории: `.env` и `.env.local` исключаются, `.env.example` доступен для публикации. Git-репозиторий проекта автоматически не создавался.

Инфраструктура и credentials для реального demo были доступны. Единственное действие вне выполненных исправлений — отзыв/замена владельцем ключа, найденного в шаблоне.
