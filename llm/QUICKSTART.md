# Запуск и подключение

Из корня репозитория:
```powershell
cd llm
node server.js
```
Сервер: http://localhost:3001. Проверки: `node --test`. Зависимостей нет; Node.js 18+.

По умолчанию используются демонстрационные вопросы. Для реальной модели нужен запущенный Ollama с уже установленной моделью:
```powershell
$env:LLM_PROVIDER="remote"
$env:LLM_MODEL="ИМЯ_ВАШЕЙ_УСТАНОВЛЕННОЙ_МОДЕЛИ"
$env:LLM_BASE_URL="http://127.0.0.1:11434"
node server.js
```
Имя модели — точное имя из вашей установки. Приложение не скачивает модель и не устанавливает Ollama. Настройки `.env.example` автоматически не загружаются. При смене переменных перезапустите сервер. При ошибке, некорректном ответе или таймауте 15 секунд возвращается `mode: mock, fallback: true` с предупреждением. Для первой загрузки большой модели этого таймаута может не хватить.

## API

`POST /api/llm/analyze` — вопросы. `POST /api/llm/card` — сборка карточки без генерации фактов. В обоих случаях `Content-Type: application/json` и тело:
```json
{"draft":"Кофейня хочет сократить списания","fields":{"data":"CSV продаж за полгода","users":"Управляющий"}}
```
Анализ возвращает `{questions:[{field,text}],mode,fallback,warning?}`. Карточка возвращает `{card,missingFields,requiresConfirmation:true}`. Неизвестные сведения остаются пустыми. Все флаги confirmed имеют значение false; исходное описание используется как context, только если явный context отсутствует. Название задачи вводится отдельно в интерфейсе.

Коды HTTP: 200 — результат (в том числе явно обозначенный fallback), 400 — неправильный ввод/JSON, 405 — неверный метод, 413 — запрос больше 64 КиБ, 415 — неподдерживаемый Content-Type. Ответ провайдера ограничен 128 КиБ. Не выводите ключ в клиент или журналы.

Демо использует правила для кофейни, логистики и образования; это не модель. Семантическая достоверность вопросов реальной модели не гарантируется схемой JSON. Рейтинг и выбор команд остаются вне LLM.

GitHub хранит код, но не запускает Node-сервер. GitHub Pages поддерживает только статическую часть. API запускается локально или на серверном хостинге. Для публичного API дополнительно нужны аутентификация, лимиты запросов и настроенный доступ из фронтенда; сейчас сервер слушает только 127.0.0.1.

Адаптер реализован по официальному контракту: https://docs.ollama.com/api/chat. Тесты проверяют контракт с подменённым HTTP-ответом; реальный запуск модели отдельно не подтверждён.
